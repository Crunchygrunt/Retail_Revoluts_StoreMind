# StoreMind — Technical Handoff

**Context:** Google Cloud AI Builder Cup 2026, Retail & Commerce track. Core claim: **"Enforced, not just scored."**
This handoff covers a single long session that added India-first seller-identity verification, ONDC catalog conformance, a live MCP agent widget, and fixed several real production bugs. Read this instead of reconstructing history from the chat.

---

## 1. High-Level Goal

Three major bodies of work landed this session, on top of the existing ACP/UCP/MCP catalog pipeline:

1. **Seller identity verification, India-first** — GSTIN was the wrong single gate (excludes the exact informal, sub-₹40L-turnover, WhatsApp/Instagram segment this product targets). Replaced with an **either-or** system: GSTIN alone / Udyam alone / UPI+PAN together / UPI+WhatsApp together.
2. **ONDC catalog conformance** — a third eligibility lens alongside ACP and UCP, computed independently, catalog-readiness only (no live network participation, no `/select`/`/init`/`/confirm`).
3. **A live, interactive MCP agent widget** on the Overview page — real Gemini function-calling against the same mounted `/ucp/mcp` endpoint Gemini CLI already proved works in production, not a canned example.

Plus: brand inference is now category-scoped (was store-wide — the exact "still undecided" gap named in the original project handoff), and several real production bugs were found and fixed via live Cloud Run log diagnosis.

**Active, unresolved bug going into the next session** (see §4): manufacture-date extraction into the new ONDC-required fields is not working, and the root cause isn't confirmed yet.

## 2. Technical Decisions & Architecture

- **India-first confirmed**, not South-Asia-wide (this was decided at the very start of this session, superseding an earlier SEA-expansion plan).
- **GSTIN**: structure + a real Luhn-mod-36 checksum, confirmed against two independently-sourced worked examples and cross-checked against `python-stdnum`'s own GSTIN module.
- **PAN**: structure only — deliberately **no invented checksum**. `python-stdnum` itself calls PAN's check digit "an undocumented checksum algorithm" and validates structure only; matched that standard rather than guessing.
- **Udyam**: structure only (`UDYAM-XX-00-0000000`), no checksum exists in the published format, no public verification API.
- **UPI ID / WhatsApp phone**: format-only checks, explicitly named `*_format_valid` (never `*_verified`) in the code itself — neither has a checksum, so combined they're still weaker evidence than GSTIN alone.
- **No live verification APIs anywhere** — explicit standing instruction from the user: *"do not check for live api... we can do api only if that api cost get cut from our gcp credit."* Everything above is offline, free, deterministic.
- **Seller-as-packer**: opt-in only (`STOREMIND_SELLER_IS_PACKER=true`), never assumed by default — a reseller of branded goods (Nike, Bata) must not have a false manufacturer claim asserted on their behalf; only genuinely home-packing sellers use the store name as packer.
- **Config split**: `deploy.env` (infrastructure — GCP project, LLM/store backend) vs. new **`seller.env`** (merchant/business facts — identity, ONDC packer/policy config). Two separate `load_dotenv()` calls in `main.py`, same mechanism, different files, so an infra change can't accidentally touch merchant config or vice versa.
- **ONDC scope, deliberately bounded**: catalog conformance only. No registry participation, no live transaction lifecycle. `ondc_eligibility.py` mirrors `ucp_eligibility.py`'s pattern but is a **single boolean**, not a 3-tier split — ONDC's schema has no "catalog-only, not checkout-ready" middle tier the way ACP/UCP do.
- **`ONDCMappingError` collects ALL applicable gaps at once**, unlike UCP's one-reason-at-a-time `UCPMappingError` — ONDC has enough independent prerequisites (domain, statutory fields, seller policy) that one-at-a-time reporting would mean several rounds of "fix one thing, discover the next."
- **MCP live widget**: the backend (`mcp_agent_bridge.py`) opens a **real MCP client session** (`streamable_http_client` + `ClientSession`, the exact pattern confirmed working in `test_mcp_http_client.py`) against the same mounted `/ucp/mcp` — deliberately not a second, parallel in-process call to `ucp_catalog.py`, so the live widget and the Gemini-CLI-proven path are provably the same code.
- **Brand inference is now category-scoped** (`infer_brand_by_category`), not store-wide. `infer_brand` (old, store-wide) is kept completely unchanged for backward compatibility with its existing tests; the vote-counting logic itself was extracted into a shared `_vote()` helper so there's one implementation, not two that could drift.
- **`main.py` had ~600 lines of a fully-commented-out old version sitting above the real, active code** (994 lines total). Harmless at runtime (Python ignores comments) but a real maintenance risk. User has since stripped it; local working copy synced to match (now 594 lines). `firestore_client.py` and `local_store.py` likely have the same dead-block pattern — not yet cleaned up.

### Real production bugs found and fixed this session
1. Deployed `seller_profile.py` was stale (pre-dated the ONDC fields) → `AttributeError` 500 on every `/ingest` — fixed by redeploy.
2. `firestore_client.list_products()` had no `order_by` → newly-ingested products were silently excluded from `/products`, masked as "ingest isn't working" — fixed with `order_by(updated_at, DESCENDING)`.
3. `local_store.list_products()` — same symptom, different cause (dict insertion order) — fixed with an explicit sort.
4. `/mcp/ask` returned `{"error": ...}`, which `api.js` doesn't check (`detail`/`reason` only) → generic "status 502" hid the real message — fixed via `HTTPException`.
5. `mcp_agent_bridge.py` had no wall-clock timeout, only an iteration cap → a question needing an unsupported capability (price-range filtering) could hang past any useful error — fixed with `asyncio.wait_for(60s)`.
6. `OverviewPage.jsx`'s live widget: typing a new question live-edited the *previous* answer's displayed question line — fixed by freezing `askedQuestion` at submit, separate from the live `question` input state.
7. A hardcoded placeholder string I nearly shipped in `ondc_mapping.py` (`month_year_of_manufacture` defaulting to `"UNKNOWN - NOT YET COLLECTED"` instead of being a reported gap like every sibling field) — caught and fixed before delivery.
